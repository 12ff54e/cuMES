# ADR-0017: Opt-in m=1 toroidal compensation in scalar WebGPU geometry

## Decision

Provide `geometry=compensated-m1` as a diagnostic precision scope for scalar
fixed-boundary 3-D browser solves. The default retains its existing compensated
poloidal reconstruction; `geometry=native` remains the uncompensated diagnostic.
Paired-f32 solves retain their existing arithmetic.

The selected scope carries four m=1 R/Z toroidal sums as explicit pairs of f32
words. Each coefficient/basis product first rounds to f32, matching the selective
native design in `9c59702`. Preserve the low words through poloidal products,
odd-mode accumulation, and paired radial normalization. The normalization is
`sqrt((ns-1)/max(surface,1))`, split into two words during host setup.

Higher odd modes retain scalar toroidal intermediates and the existing paired
poloidal products with visibly single-word inputs, as in `0d8482a`. Scalar
toroidal intermediates remain available unchanged for angular derivatives,
lambda, and constraint geometry. A Kahan correction is not reinterpreted as a
paired low word. No native f64 shader arithmetic is introduced.

The inverse's reusable intermediate buffer appends four high/low m=1 planes and
the radial constants only when this diagnostic is selected. Host normalization
tables are cached by radial shape; their small upload shares the existing queue
ordering and adds no completion fence. The scope persists across multigrid
stages and is recorded in output provenance.

## Numerical consequences

This is Class C when enabled: preserving radial detail changes the scalar
residual trajectory and adaptive controller decisions. It does not change the
force model, prescribed boundary/current, grids, residual thresholds, validity
gates, or stage iteration caps. It is not enabled automatically based on native
CUDA qualification.

The paired inverse generated by the precision preprocessor has identical
arithmetic before and after this change. Default scalar qualification retains
the recorded controller trajectory and scientific payload hashes on the same
adapter.

## Validation

The operator regression exercises all four R/Z harmonic families with nonzero
toroidal modes on `ns=4` and the minimum `ns=2` grid. The m=1 sums contain small
terms that are lost by scalar intermediate storage and exposed by cancellation
with m=3. It compares odd positions with the independent double host reference,
and requires bitwise equality of all untouched inverse fields and constraint
outputs, including signed zero.

The analytic theta=zeta=0 case requires exactly
`f32(sqrt(ns-1) * 2^-27)` on surface 1, while the previous scope gives zero.
Elsewhere the unit-scale fixture allows two final f32 ULPs plus `2^-45`
absolute: near angular zeros, cancellation exposes the rounding of the paired
sums and double reference before final f32 conversion. This absolute allowance
is far below the lost `2^-27` term and does not relax the analytic assertion.

The recorded Chrome 152 / RTX 3060 Ti qualification includes the complete
conformance suite and single/multigrid W7-X solves at the browser's scalar
`1e-5` tolerance. The default conformance and W7-X paths preserve all 304 and
1,134 controller records respectively. The new scope converges in 895 effective
iterations on the single grid and 1,163 across three grids, versus 1,129 and
1,571 with the default scope. Both new-scope paths were repeated: all 900 / 1,177
controller records and scientific state/field hashes were exact. These are
measured case results, not general acceptance counts or wall-time speedups.

The single-grid comparison starts from the same spectral-state hash. Residuals
already differ on that first evaluation, adaptive damping first differs on
attempt 2, and the first discrete checkpoint decision differs on attempt 279.
This confirms the Class C classification rather than unchanged-controller
numerical equivalence.

Both new-scope scientific outputs contain finite state and fields, a strictly
single-sign coordinate Jacobian, and exactly zero radial magnetic field. Their
prescribed R/Z LCFS coefficients agree bitwise between the two stage paths and
with the matched default outputs. All four outputs retain the prescribed
folded boundary coefficients bitwise and pass the same finite, Jacobian and
radial-field invariants. Relative to the default single/multigrid outputs, the
new scope changes non-axis Rcc by at most `6.094e-4` / `7.824e-4` m and lambda
coefficients by at most `3.442e-3` / `4.308e-3`.

An independent VMEC++ 0.7.0 CPU run uses the unchanged `inputs/w7x.json` with its
original `1e-12` stage tolerances. The new-scope single/multigrid volumes differ
by `1.91e-8` / `1.82e-8` relative. Maximum non-axis spectral differences to this
reference are:

| Scope | Single-grid Rcc (m) | Multigrid Rcc (m) | Single-grid lambda | Multigrid lambda |
| --- | ---: | ---: | ---: | ---: |
| Default | 4.037e-3 | 3.022e-3 | 2.872e-2 | 2.116e-2 |
| Compensated m=1 | 4.646e-3 | 3.805e-3 | 3.202e-2 | 2.546e-2 |

These report independent diagnostic differences at different residual
tolerances. They do not support an accuracy-improvement claim, establish tight
spectral agreement, or replace cuMES's residual and geometry gates.

The scope remains experimental. This qualification does not establish a
free-boundary benefit, a scalar tolerance below `1e-5`, or performance on other
adapters. A browser checkpoint replay is not covered by the current browser
input path.
